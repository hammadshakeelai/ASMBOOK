# ASMBOOK — Accuracy policy

"Extremely accurate" is a **CI property**, not a claim. This document defines
how accuracy is enforced and what happens when oracles disagree.

## The three authorities

1. **Intel/8086 architectural documentation** — the specification. Where the
   spec defines behavior, the spec wins.
2. **NASM** — the encoding authority for supported syntax.
3. **DOS emulators (DOSBox-X native, v86, js-dos)** — *compatibility* oracles
   for how DOS-era software behaves. **An oracle is not a specification.**

## Result classes

Every generated differential test is tagged:

- `MUST_MATCH` — architecturally defined; all engines must agree
- `IMPLEMENTATION_DEFINED` — legal variation; recorded, not enforced
- `UNDEFINED_DONT_COMPARE` — e.g. undefined flag results after some shifts/
  MUL/DIV; the kernel picks a deterministic value, tests never assert it
- `NOT_SUPPORTED` — outside the 8086 course subset; rejected at parse time

We never "fix" the kernel to imitate an oracle where the architecture does
not prescribe the behavior.

## CI tiers

| Tier | When | What |
|---|---|---|
| 1 | every commit | 375+ engine cases, parser tests, arithmetic edges, assemble→disassemble→assemble round-trips |
| 2 | every PR | encoder differential: generated sources through our encoder vs vendored WASM NASM — byte equality |
| 3 | nightly | small `.COM` programs whose guest harness writes a `RESULT.BIN` (registers, flags, memory hashes) before exiting; run under **DOSBox-X (native, pinned config: cputype=8086, fixed cycles)** as primary oracle and **v86 (headless FreeDOS)** as independent secondary |
| 4 | release | Playwright product smoke: UI → js-dos → assemble → run → output |

## Golden corpus

Every confirmed engine bug becomes a permanent fixture with its oracle-
verified expected state. Bugs found by fuzzing record their seed; the seed
case is added to the suite. The corpus only grows.

## Performance

The interpreter targets ≥1M instructions/sec on the fast path (mid-range
laptop). CI compares **median** benchmark results against a stored baseline
and flags relative regressions >15% — never absolute numbers on shared
runners.

## Public ledger

The site publishes `accuracy-ledger.json` (generated by CI): which
instruction forms × addressing modes are covered, by which test class, and
their verification status. The UI may label the interpreter lane with this
coverage — honestly, down to the unverified cases.
